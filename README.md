
## バックエンド + Web API (Express + TypeScript + Prisma + PostgreSQL + Docker + JWT)

下記、API仕様をもとに Web API を実装してください。

### API 仕様

https://vws-api-spec-host.netlify.app/specs?id=express-web-api

### 認証について

- `/auth/signup` でユーザ登録
- `/auth/login` でログインで認証を行うように実装してください。

それぞれのエンドポイントでは jwt トークンを発行して各エンドポイントでは、
Authorization ヘッダー内のトークンを検証して、トークンが不正な場合は 401 Unauthorized で返すように実装してください。

### 技術スタック

- Express
- TypeScript
- Prisma
- PostgreSQL
- Docker
- JWT

## Claude Code での開発の流れ

このリポジトリには、仕様書づくりから PR までを進める Claude Code のコマンドを用意しています。

### 全体の流れ

```
/spec ──▶ 見直す ──▶ /plan ──▶ 見直す ──▶ /implement ──▶ 確かめる ──▶ /pr
 仕様書       人        プラン      人        実装・テスト       人         PR
                                              ・レビュー
```

各コマンドは下書きまでを作り、次に進む前に人が見直す前提です。課題の API を一通り作るときの手順と確認項目は、[課題の実装チェックリスト](docs/implementation-checklist.md) にまとめています。

| 順番 | コマンド                     | すること                                                                                       | できるもの                       |
| ---- | ---------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------- |
| 1    | `/spec <作りたい機能の説明>` | API 仕様とテストを調べて仕様書の下書きを書き、`feature/<slug>` ブランチを作る                  | `_specs/<slug>.md`               |
| 2    | `/plan <仕様書のパス>`       | 仕様書をもとに、タスクの分け方と担当範囲を決める                                               | `_plans/<slug>.md`               |
| 3    | `/implement <プランのパス>`  | タスクをサブエージェントで並列に実装し、統合・チェック・テスト（`test/`）・レビューまで行う    | 実装のコミット                   |
| 4    | `/pr`                        | `/review` とセルフレビューで確かめ、blocking な問題が無ければ push して PR を作る              | main 向けの PR                   |

いつでも使えるコマンド:

| コマンド               | すること                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------- |
| `/cmt [ヒント]`        | 変更内容から種類と絵文字を選び、`✨ feat: 〜` の形の日本語メッセージでコミットする                 |
| `/review [仕様書のパス]` | 作業ブランチの差分を、仕様書・プランとの突き合わせ（`api-reviewer`）・バグ（`/code-review`）・セキュリティ（`/security-review`）の 3 つでレビューする。コードは変更しない |

### 使い方の例

```
/spec タスクの作成 API（POST /users/tasks）
  → _specs/create-task.md を見直す。<!-- 要確認: 〜 --> が残っていれば決めて書き換える

/plan _specs/create-task.md
  → _plans/create-task.md を見直す。タスクの分け方・公開 API・判断した点を確かめる

/implement _plans/create-task.md
  → 報告された要件の対応状況と、残った指摘を確かめる。curl で動かしてみる

/pr
```

### 人が見直すところ

- **仕様書**: 要件は HTTP リクエストで確かめられる粒度になっているか。`要確認` が残っていないか。対象外は妥当か。
- **プラン**: 同じ段階のタスクで担当範囲のファイルが重なっていないか。要件の割り当てに漏れがないか。
- **実装**: `/implement` の報告で、テストの結果・残した指摘・サブエージェントが判断した点を確かめる。

### 注意

- `/spec` と `/pr` は、作業ツリーに未コミットの変更があると止まります。先に `/cmt` でコミットしてください。
- `test/` は課題の判定用なので、どのコマンドも変更しません。
- `/implement` のテストでは `docker compose up -d`・`npm run db:seed`・`npm run dev` を実行します。ポート 3000 と 5432 を空けておいてください。
- `/implement` では `npm`・`npx prisma`・`docker compose`・`git` のコマンドを何度も実行するので、許可の確認が多く出ます。
- コマンドはまだ実際の課題で動かしていません。途中で止まったり手順どおりに動かなかったりしたら、`.claude/commands/` の該当ファイルを直してください。

### ファイルの置き場所

| パス                    | 中身                                                     |
| ----------------------- | -------------------------------------------------------- |
| `.claude/commands/`     | 上のコマンドの手順                                       |
| `.claude/agents/`       | `implementer`（実装）・`api-reviewer`（仕様書・プランとの突き合わせ）のサブエージェント |
| `_specs/_template.md`   | 仕様書のテンプレート                                     |
| `_plans/_template.md`   | プランのテンプレート                                     |
| `docs/implementation-checklist.md` | 課題の API を一通り作るときのチェックリスト   |

## 課題の進め方

### 1. 課題の最終ゴールを確認する

デモを確認したり、メンターに確認してこの課題で達成すべき内容を確認してください。

### 2. 必要な概念を確認する

課題でやる全体像を把握した上で課題に必要な概念を学んで取り組んでください。
この課題ではリポジトリをフォークするのではなく、自分のリポジトリを作成して取り組んでください。

[参考資料](./docs/documents.md)

### 3. 実装に取り組む

実装量が多いので適切なタイミングでメンターに方向性のチェックを依頼するようにしてください。

Hint: 方向性のチェックを行う際は、プルリクエストを使用して現時点のコードを共有しながら進めましょう。

- [プルリクエストを出す上での注意点](https://lab.ver-1-0.net/posts/pr-points/)

#### チェック項目

- [ ] API 仕様に則りコードが実装されていること
- [ ] APIサーバが下記仕様に則っていること
  - [ ] Seed データが用意されていること
  - [ ] リクエストログが出力される
  - [ ] クエリログが出力される

仕様に則っているかどうかは、[./test](./test) ディレクトリにあるテストコードを実行して確認してください。

1. `npm run db:seed`
2. `npm run dev` でサーバ起動

の手順を踏んだあとに、test ディレクトリにあるテストコードを実行して、テストが全て成功すれば仕様に則っていると判断できます。
詳細は [./test/README.md](./test/README.md) を確認してください。

#### 4. メンターに最終レビューを依頼する

この課題では、アプリケーションの公開は不要なので実装完了次第レビューを依頼してください。
