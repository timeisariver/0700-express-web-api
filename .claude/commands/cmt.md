いまの変更を、目的ごとに分けて、下のルールに従ったメッセージでコミットする。`$ARGUMENTS` があれば、メッセージのヒントとして使う。

## コミットメッセージのルール

形式は `<絵文字> <種類>: <要約>`。

| 種類     | 絵文字 | 使う場面                                                   |
| -------- | ------ | ---------------------------------------------------------- |
| feat     | ✨     | 機能の追加                                                 |
| fix      | 🩹     | バグの修正                                                 |
| docs     | 📝     | ドキュメント・仕様書・プランだけの変更                     |
| style    | 💄     | フォーマット・空白・import の並びなど、動作に関係しない書き方だけの変更 |
| refactor | ♻️     | 動作を変えないコードの整理                                 |
| chore    | 🔧     | 設定・ツール・依存パッケージ・スクリプトの変更             |
| revert   | ⏪     | 以前のコミットの取り消し                                   |

- **要約**は日本語で、何をしたかを 50 文字くらいまでで書く（例: `✨ feat: タスク一覧 API を追加`）。末尾に句点を付けない。
- 理由や補足が要るときだけ、1 行空けて本文を書く。
- 複数の種類にまたがるときは、変更の中心になっている種類を選ぶ（例: 機能の追加とそのための設定変更なら `feat`）。
- `revert` は `⏪ revert: <取り消すコミットの要約>` とし、本文に取り消すコミットの SHA を書く。

## 1. 確認

1. `git status --short` で変更があることを確かめる。無ければ「コミットする変更がありません」と伝えて止める。
2. 現在のブランチが main なら、止めてユーザーに確認する。
3. `.env` や秘密鍵など、コミットしてはいけないファイルが変更に含まれていれば、ステージせずにユーザーに伝える。

## 2. 何をコミットするか決める

### 対象を決める

- ステージ済みの変更（`git diff --cached`）があれば、対象を**それだけ**に絞る。未ステージの変更と未追跡のファイルは入れない。
- 無ければ、`git diff` と未追跡のファイルを確かめ、すべてを対象にする。
- どちらの場合も、1. の 3 で除いたファイルは入れない。

### コミットを分ける

対象の中に目的の違う変更が混ざっていれば、**ステージ済みかどうかに関係なく**、ファイル単位で分けて複数のコミットにする。

- 分ける目安: 種類が違う（例: `feat` と、それと関係ない `chore`）、関係ないリソースや機能にまたがる、リファクタリングと機能変更が混ざっている。
- 機能の追加と、そのために要る設定やテンプレートの変更のように、一緒でないと意味が通らないものは分けない。
- 1 つのファイルの中で混ざっている場合は、ファイルを分けずにどれか 1 つのコミットに入れる。
- 分けるときは、後のコミットが前のコミットに頼る順（例: 設定 → それを使う機能）でコミットする。
- `$ARGUMENTS` に「1つにまとめる」「分けない」などと書かれていれば、分けずに 1 つのコミットにする。

分けるときの手順: 対象がステージ済みだった場合は、対象のファイル一覧を控えてから `git restore --staged .` でいったんステージを外す。そのうえで、コミットごとに `git add <ファイル>` → `git commit` を繰り返す。対象に入れなかったファイルはステージしない。

## 3. コミット

1. `git diff --cached` で中身を読み、上のルールで種類・絵文字・要約を決める。最近の書き方は `git log --oneline -10` で確かめる。
2. `git commit` する。pre-commit などのフックが失敗したら、`--no-verify` で飛ばさずに原因を直してからコミットし直す。直し方が分からなければ止めてユーザーに伝える。

## 4. 報告

コミットごとに、短い SHA とメッセージを 1 行ずつ伝える。コミットしなかったファイルがあれば、その理由も伝える。
