# 課題の実装チェックリスト

AI（`/spec` → `/plan` → `/implement` → `/pr`）で課題の API を一通り作り、自分で確認して、メンターに説明できるところまで進めるためのチェックリスト。

目安は 4〜7 時間。自分が集中する時間は 3〜4 時間で、残りは `/implement` の待ち時間。2 回に分けるなら、1 回目は「3. 実装する」まで、2 回目は「4. 自分で確認する」から。

## 始める前に

- [ ] main に切り替えて `git pull`
- [ ] Docker Desktop が起動している
- [ ] ほかの PostgreSQL のコンテナ（チュートリアルなど）を止めている（ポート 5432 がぶつかるため）
- [ ] ポート 3000 を使っているものが無い
- [ ] 新しい Claude Code のセッションを開く

## 1. 仕様書を作る（20〜40 分）

- [ ] `/spec 課題の API を全部（test/ が全部通るところまで）`
- [ ] `_specs/<slug>.md` を見直す
  - [ ] `<!-- 要確認: 〜 -->` が残っていれば、決めて書き換える
  - [ ] 「対象外」が妥当か（リフレッシュトークンの更新、ログアウトなど）

## 2. プランを作る（20〜40 分）

- [ ] `/plan _specs/<slug>.md`
- [ ] `_plans/<slug>.md` を見直す
  - [ ] 段階が「土台 → 認証・ユーザー・プロジェクト・タスク → 結線」になっているか
  - [ ] 同じ段階のタスクで、担当範囲のファイルが重なっていないか
  - [ ] 「判断した点」に納得できるか

## 3. 実装する（1〜2 時間、ほぼ待つだけ）

- [ ] `/implement _plans/<slug>.md`
- [ ] 報告で次を確かめる
  - [ ] 要件ごとの対応状況
  - [ ] `test/` の結果（通らなかったもの）
  - [ ] 直さずに残した指摘

## 4. 自分で確認する（課題の完了条件、30 分〜1 時間）

- [ ] `npm run db:seed` → `npm run dev` のあと、`test/` で `npm run test` が全部通る
- [ ] Seed が入っている（`npx prisma studio` で users・projects・tasks に行がある）
- [ ] `npm run dev` のターミナルにリクエストログが出る（例: `GET /api/v1/users/me 200`）
- [ ] 同じターミナルにクエリログ（SQL）が出る
- [ ] `curl` か Postman で叩いてみる
  - [ ] ログインして `accessToken` を受け取る
  - [ ] `Authorization: Bearer <accessToken>` を付けて `/users/me` が 200
  - [ ] ヘッダーを外すと 401

## 5. 説明できるようにする（メンターのレビュー用、1〜1.5 時間）

- [ ] `GET /users/tasks` を、ファイルを開いてたどる
  - [ ] 認証ミドルウェア（JWT を確かめる）
  - [ ] Routes → Controller → Model（Prisma）→ DB
- [ ] 各ファイルの役割を言える
  - [ ] `schema.prisma`（テーブルの形）
  - [ ] マイグレーション（DB の形の変更履歴）
  - [ ] `seed.ts`（初期データ）
  - [ ] `.env`（秘密の値。コミットしない）
- [ ] メンターに聞きたいことをメモする

## 6. PR を作る（15〜30 分）

- [ ] `/pr`（大きさについて聞かれたら、今回は 1 つの PR にすると答える）
- [ ] メンターにレビューを依頼する

## 詰まったとき

- Docker・DB に接続できない → エラーをそのまま AI に貼る。ポート 5432 の取り合いを最初に疑う
- テストが落ちる → 「`test/` の失敗を直して。`test/` は変更しないで」と頼む
- コマンドが途中で止まる・手順どおりに動かない → `.claude/commands/` の該当ファイルを AI に直してもらう（初めて動かすので、手直しが出る前提）
- 時間が足りない → 「ここまで作った・ここで詰まった・ここが分からない」をメモしてメンタリングに持っていく
